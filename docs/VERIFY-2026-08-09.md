## 2. Are the real form windows populating?

This is the one most likely to fail quietly, because the whole chain
(ESPN → sheet → reader → feature) has to work.

```sql
SELECT league, market,
       COUNT(*) n,
       COUNT(DISTINCT ROUND((features->>'recent_form_l1_diff')::numeric,4)) d_l1,
       COUNT(DISTINCT ROUND((features->>'recent_form_l3_diff')::numeric,4)) d_l3,
       COUNT(DISTINCT ROUND((features->>'recent_form_l5_diff')::numeric,4)) d_l5
FROM prediction_features
WHERE date >= CURRENT_DATE - 1
GROUP BY 1,2 ORDER BY 1,2;
```

**Want:** `d_l3` and `d_l5` in the high single digits or better, and **not all
equal to each other**. Before the fix these were 3, 3, 3 and perfectly
collinear.

**If still 3/3/3:** the FormL1/L3/L5 columns are not reaching the feature
layer. Check in this order — the Team Stats sheet actually has FormL1/FormL3/
FormL5 in columns T/U/V; `enrichRecentForm` logged
`recent form games/team min=… max=…` with max near 10 (not 5); the readers are
picking up `row[19..21]`.

`d_l1` legitimately sits at 2–3 (it is a difference of two binary outcomes) —
that is correct, not a failure.

## 5. Did the spread close-side bug actually stop?

Only meaningful once today's games have frozen, so run it tomorrow evening or
the day after.

```sql
SELECT game_date, COUNT(*) n,
       COUNT(*) FILTER (WHERE SIGN(line::numeric) <> SIGN(close_line::numeric)) side_flip,
       COUNT(*) FILTER (WHERE ABS(clv_prob_delta) > 0.10) impossible
FROM performance_log
WHERE pick_regime='v2_clv' AND market='spread'
  AND game_date >= CURRENT_DATE - 1 AND close_line IS NOT NULL
GROUP BY 1 ORDER BY 1;
```

**Want:** `side_flip = 0` and `impossible = 0`. Previously 11 of 109 spread
rows flipped side.

Also check the `freeze` log for `sideMismatch` — a non-zero count means the
new guard is correctly *refusing* to write a corrupt close, which is the
intended behaviour, but a persistently high number means something upstream
is still wrong.
